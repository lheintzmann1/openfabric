# OpenFabric art assets (SVG, one file per thing)

Every picture in the game is an SVG file named after its id. Replace any file with your own art and it is used instead —
no code changes. Press **F9** in game to reload edited SVGs without restarting.

| Folder | One file per… | Name | Notes |
|---|---|---|---|
| `items/` | item | `data/items.json` `id` (e.g. `iron_plate.svg`) | square icon, any viewBox; drawn on belts, in slots, in the inspector |
| `buildings/` | building | `data/buildings.json` `id` | art for the whole footprint: use a viewBox with the building's `w:h` aspect (a 2x2 machine = square, 3x2 = 3:2). Drawn pointing **east** at rotation 0 |
| `resources/` | ore / fluid node | resource item id (`iron_ore.svg`, `crude_oil.svg`) | drawn on a single map tile (rotated randomly for ores) |
| `terrain/` | terrain type | `deep_water, water, sand, grass, forest, rock, cliff, snow` | **tileable** square tile; the game rotates/shades it per tile. Its average colour also colours the zoomed-out map |
| `research/` | research node | `data/research.json` `id` | square icon |
| `ui/` | interface icon | Material icon name (`close.svg`, `bolt.svg`, …) | monochrome white glyph — the game tints it |

Rules of thumb
* Directional buildings (`belt`, `splitter`, `merger`, `underground`, `loader`) are rotated with the building; every other
  building only turns by quarter-turns when its footprint is rotated, so text/glyphs stay readable.
* `items/`, `buildings/`, `resources/`, `research/` art keeps its own colours. `ui/` art is tinted, so draw it white.
* Missing file → the game falls back to a "?" glyph (items/buildings/…) or the built-in Material icon (ui/).
* Per-user overrides without touching the repo: put files in `~/.local/share/OpenFabric/assets/<folder>/<id>.svg`
  (`%LOCALAPPDATA%\OpenFabric\assets` on Windows); they take priority over this folder.
* The defaults were generated by `tools/gen_assets.py` from the Material Icons font and `data/*.json`. Re-running it overwrites
  files; use `--keep-existing` to only create missing ones (e.g. after adding new items to the data).
